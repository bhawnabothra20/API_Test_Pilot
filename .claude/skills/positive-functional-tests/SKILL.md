# Positive: functional

Generated by the plugin `scripts/design/generators/positive-functional.ts`.

## Per endpoint
1. **Happy path** - valid request returns the documented success code (200/201/204) and the required
   fields. GET list: non-empty array + schema. GET item: id in the body equals the requested id.
   POST/PUT/PATCH: request fields echoed by the response entity (for POST the entity may be nested, e.g.
   `booking` inside `{bookingid, booking}` - use `createEntityPath`).
2. **Optional fields** - POST/PUT with required fields only; the happy path already sends all fields.
   If every field is required, record it in `notApplicable`.
3. **Idempotency** - GET twice: same status and body; PUT twice with the same body: same result;
   DELETE twice: second call returns 404 (persistent APIs) or the same success.
4. **Filters / search / sort** - for each documented query parameter:
   - field present in list items -> every returned item must match (`filter-all`);
   - field only on the full entity -> create a resource with a known value, filter, and expect the new id
     in the result (`filter-contains`, cleans up afterwards).
5. **Pagination** - only when documented (`page`, `limit`, `_page`, `_limit`, `per_page`, `size`);
   otherwise add to `notApplicable`.

## CRUD lifecycle (one per resource, on its POST endpoint)
create -> read back (must equal payload) -> PUT (must equal replacement) -> read again -> PATCH ->
DELETE -> read again must return 404. Cleanup in `finally` if any step fails before delete.
If documentation says writes are simulated (`persistsWrites: false`), the lifecycle still asserts real
persistence - its failure is a documented-behaviour finding, never hidden.

## Ids for item endpoints
- `created` when the API persists writes and cleanup is possible (fresh, isolated data);
- `existing` otherwise (first id from the collection, falling back to the discovered sample id).

## Example
`TC_JSONPLACEHOLDER_POSTS_POST_001` "POST /posts with a valid request returns 201 and the required
fields" - asserts 201, JSON Content-Type, `PostsPostResponse` schema, `expectEcho(body)` and response
time.
