# Negative tests

Generated by the plugin `scripts/design/generators/negative.ts`.

## Inputs (per body endpoint; PATCH skips "missing required" and "{}")
| Case | Data |
|---|---|
| Missing required field, one at a time (leaves, max 10) | valid body with the field removed (`setAtPath(body, path, undefined)`) |
| Null value (top-level required, max 5) | `{ ...body, field: null }` |
| Empty string (first required string) | `""` |
| Empty object / no body / malformed JSON / array instead of object | `{}`, raw `""`, raw `{"broken": `, `[body]` |
| Wrong type (top-level fields, max 8) | string->12345, number->"not-a-number", boolean->"not-a-boolean", array->object, object->array |
| Invalid enum / invalid format | `NOT_A_VALID_ENUM`, `not-an-email`, `2024-13-45`, `1234-not-a-uuid` |
| Wrong Content-Type | valid JSON sent as `text/plain` -> 415/400 |
| Injection-style input (first free-text string) | SQL `' OR '1'='1'; DROP TABLE users; --`, `<script>alert("x")</script>`, `%00\";{}$\`|&<>` - **rejected or stored safely**, never 5xx |
| Duplicate creation | only where uniqueness applies (`username`, `email`, or "unique" in the field description) -> 409/400/422 |

## Per path / id
- Unknown id (`999999999`) -> `notFoundStatus` (404).
- Invalid id format (`abc-!@#`) -> 400.
- Unsupported method on the path (first of DELETE/PATCH/PUT/POST not documented) -> 405 (or 404).
- GET collections: wrong-typed query value -> 400; unknown query parameter -> ignored or rejected, never 5xx.

## Assertions (every negative test)
```ts
expectNoServerError(res);            // never a 5xx - checked first so a 500 is reported as such
expectStatus(res, [400, 422]);        // the correct 4xx
expectErrorBody(res, 'safe');         // 'json' when an error schema is documented; no stack traces,
                                      // internal paths, SQL errors (LEAK_PATTERNS)
expectResponseTime(res, limits.responseTimeMs);
```
`tolerant` variants (injection, unknown query, whitespace) allow the success code as well, but still
assert no 5xx and no leak.

## Status expectations
Use the documented 4xx (`badRequestStatus`). When validation rules are inferred (no spec or apiDoc),
allow `400` or `422`, mark the case `assumptionBased`, and let triage classify acceptance of invalid
input as `Contract/Spec mismatch` rather than a defect.
