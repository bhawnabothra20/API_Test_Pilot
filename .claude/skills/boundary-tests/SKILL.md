# Boundary tests

Generated by the plugin `scripts/design/generators/boundary.ts`.

## Limits
Use `minLength/maxLength/minimum/maximum/minItems/maxItems` from the spec. Without them use
`summary.defaults` (strings 1..255 for required fields, numbers 0..2147483647 - ids from 1, arrays up to
100) and write the assumption into the case (`assumptionBased: true`) so reports show it.

## Depth per method
| Method | String field 1 | Other strings | Number field | Dates | Arrays |
|---|---|---|---|---|---|
| POST | 0, 1, min-1, min, max, max+1, 10,000 + unicode/emoji + leading/trailing whitespace | max+1 (up to 3 fields) | min, min-1, max, max+1, 0, -1, 1e15, 1.5 for integers | leap day, impossible date, 9999-12-31, epoch | empty, 1, max, max+1 |
| PUT | 0, max+1, 10,000 | - | min-1, max+1 | leap day, impossible date | - |
| PATCH | max+1 | - | min-1 | - | - |

Duplicated values (e.g. min = 1) are generated once. Within range -> success code (and exact echo on
POST); out of range -> 400/422.

## Ids, queries, pagination
- Item endpoints: id `0` and `9007199254740993` (2^53+1); GET additionally `-1` and `1.5` -> 404/400.
- GET collections: a 10,000-character query value (200/400/414) and a unicode/emoji value - never 5xx.
- Pagination (only when documented): page first-1, first, past-last; limit 0, max, max+1.

## Example
`TC_RESTFUL_BOOKER_BOOKING_POST_045` "POST /booking "totalprice" = minimum-1 is rejected" with data
`{ ..., "totalprice": -1 }`, assumption `"totalprice" range not documented; assumed 0..2147483647.`
