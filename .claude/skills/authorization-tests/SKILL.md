# Authorization tests (OWASP API Top 10)

Generated by the plugin `scripts/design/generators/authorization.ts` (category `Authorization`), coded by
`scripts/generate-specs.ts` with helpers from `shared/helpers/authz.ts`, triaged by
`scripts/triage-failures.ts`, visualised by `scripts/access-matrix.ts`.

## One identity, no OAuth (user decision - do not reintroduce)
The agent tests with **one credential identity: admin** (`<API>_ADMIN_TOKEN` / `_API_KEY` /
`_USERNAME`+`_PASSWORD`; missing -> the test is SKIPPED with the variable names, never passed). There are no
normal-user identities, so **BOLA (API1), BFLA (API5) and wrong-role checks are not generated**. OAuth2 flows
are not run, so there are **no scope checks**; an OAuth2-only API needs a ready access token in
`<API>_ADMIN_TOKEN`. `notApplicable` records this for every API.

## Checks
| Variant | OWASP | When generated | Pass condition |
|---|---|---|---|
| `mass-assignment` | API3:2023 BOPLA | create/update of resources that persist writes and have a GET item | body + privileged fields (`role`, `isAdmin`, `is_admin`, `owner`, `ownerId`, `createdAt`, schema readOnly fields; minus documented writable ones) -> 2xx with fields ignored, or 400/422; re-read must not hold the sent values |
| `data-exposure` | API3:2023 | every JSON GET | no sensitive field names (password, secret, token, api_key, ssn, credit card ...) at any depth; with a documented schema also no undocumented fields |
| `token-hygiene` | API2:2023 Broken Authentication | once per API, on a protected endpoint | token in the query string, JWT `alg:none`, tampered signature, reuse after logout (when a logout endpoint + login exist) -> 401/403 (exact code when documented) |

Every case keeps the mandatory assertions: status (denials via `expectAccessDenied`: never 2xx, never 5xx,
expected 4xx), headers/leak-free error body, schema on successful reads, business fields (privileged
values, ids) and response time. Everything created is deleted. Inapplicable checks go to `notApplicable`
with the reason (simulated writes, no logout, no token-based auth).

## Safety
- Tokens never appear in test data, reports, the access matrix or MCP output: the query-string check's URL
  is redacted, mutated tokens are registered for redaction, Playwright traces are off.
- A fresh login session is used for the logout check so the shared token stays valid.

## Triage
Assertion markers (do not change): `Authorization bypass` -> Real API defect, High, API2 (token hygiene);
`Sensitive field exposed` / `Mass assignment` -> Real API defect, High, API3; `Undocumented field
returned` -> Contract/Spec mismatch, Low, API3. Items carry `severity` and `owasp`.

## Reports
`reports/access-matrix.json` + "Access matrix" section in `summary.html`: endpoints x identities (admin,
none, invalid, expired, malformed, wrongScheme, token-in-query, alg-none, tampered, fresh-token) with
expected vs actual status; bypass cells highlighted with the OWASP id. "Authorization findings" lists
severity + OWASP per defect.
