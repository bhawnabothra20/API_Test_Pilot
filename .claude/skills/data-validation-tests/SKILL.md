# Positive: data validation

Generated by the plugin `scripts/design/generators/data-validation.ts`; schemas by `schema-validator`.

## Cases per endpoint
1. **Schema** - response parsed with the zod schema of the endpoint: type, format and presence of every
   field; for arrays `z.array(item)` validates **every** item, not only the first.
2. **Formats / enums / ranges** - generated when the schema has `format` (date `YYYY-MM-DD`, date-time
   ISO 8601 with offset, email, uri, uuid), `enum`, `minimum`/`maximum`. Title lists the fields checked.
3. **Headers** - `Content-Type` matches the documented type (`application/json`, or e.g. `text/plain`).
   Caching headers only when the spec documents them.
4. **Response time** - `<= RESPONSE_TIME_MS` (default 2000 ms) per request.
5. **Exact echo** (POST/PUT/PATCH) - every leaf value sent comes back with the same value and type: no
   truncation, trimming, rounding or string/number conversion (`expectEcho`).

All positive tests (not only these) also assert status, headers, schema, business fields and time; the
data-validation cases make each concern an explicit, separately reported test.

## Example
```ts
const res = await api.send({ method: 'GET', path: '/users', identity: 'default', ...fromData(input) });
expectStatus(res, [200]);
expectJsonContentType(res);
expectResponseTime(res, limits.responseTimeMs);
const body = expectSchema(res, S.UsersGetResponse); // every item: email().url() formats, nested address.geo
```
